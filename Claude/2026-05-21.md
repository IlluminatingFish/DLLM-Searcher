### 3. 低准确率原因分析

**第一层：算法层面 — DPO 不适合多轮 Agentic 任务**

DPO 是为单轮偏好对齐设计的，与多轮序列决策任务有根本矛盾：
- DPO loss 均匀分布在整个 completion，无步骤级信度分配（credit assignment）
- 离线 DPO 与在线 eval 存在分布偏移
- espo 项目里的 `search_answer_reward`（-1/0/0.8/1.0）才是正确的在线 RL 信号

**第二层：数据层面 — Chosen/Rejected 信号太弱**

train.jsonl（2236对）中：
- chosen 100% 有 `<|box_start|>`（有答案）
- rejected 88.6% 也有 `<|box_start|>`（也有答案）

DPO 只在学"哪种答案更好"，未学"是否答题"。理想的 rejected 应该是跑满 max_turns 无答案的轨迹。

**第三层：Eval 层面 — answer_rl bug（已修复）**

原始 `answer_rl` 在 block 第 63 个位置强制插入 `<|box_start|>`，模型未在此位置学过答题，故忽视该信号，57% 样本跑满 max_turns 无输出。已修复为 `instruction_injection`。

### 4. 论文是否从头有问题？

**结论：不是。** 问题分层：
- 工程 Bug（可修）：extract_answer、answer_rl ← 直接压低了测出来的数字
- 数据质量（可改）：重建 DPO 数据，加入无答案轨迹作为 rejected
- 算法选择（研究 trade-off）：DPO 作为 baseline 合理，但 Online RL 是更强方向
- 核心思路（没有问题）：dLLM + Agentic Search 是真实研究问题

修复 Bug + 改善数据后，保守估计准确率可从 5% 提升到 15-25%。换 Online RL 还能进一步提高。

## 四、重复退化现象分析

在训练集 eval 中观察到严重的重复退化（repetition degeneration）：
- "check common works. Let's start with director writer collaborator works for both..." 无限循环
- "Louis Louis New Louis San Louis Louis Louis Louis Louis Louis..." 崩溃性重复

### 根本原因

**① Block 内正反馈循环（最根本）**

SDAR 每次生成 128-token block，所有位置同时去噪，block 内是全注意力（非因果）。位置 A 看到其他位置生成了重复内容，会倾向于生成同样内容，进而强化其他位置——双向正反馈锁死。AR 模型逐 token 生成，不存在此问题。

**② 跨 Block 无重复惩罚**

AR 模型有 `repetition_penalty`（降低已生成 token 的 logit）。dLLM scheduler 在每个 block 的 postprocess 中对 logits 无任何跨 block 修正，前一 block 生成了什么，后一 block 完全不知道。

**③ Low-confidence-static 重掩策略加剧锁死**

当前使用 `REMASKING_STRATEGY = "low_confidence_static"`：优先提交高置信度 token。若模型对重复内容"很自信"，这些 token 在第一步就被提交，后续去噪步骤无法逃脱退化吸引子。

**④ 多轮 Context 超出训练分布**

SFT 训练时 context 长度固定。多轮搜索中 context 随轮次增长，到第 4-5 轮时已超出 SFT 数据的长度范围。dLLM 对此更敏感，因每个 block 的初始条件来自整个 context 的注意力。

| 问题 | AR 模型 | dLLM (SDAR) |
|---|---|---|
| Block 内正反馈 | 不存在 | 严重 |
| 跨 block 重复惩罚 | 有 | 无 |
| 高置信度锁死 | temperature 可缓解 | remasking 提前锁定 |
| Context 超长退化 | 相对平滑 | 更敏感 |
